Project 27  AI-Based Delivery Optimizer 
Project Description 
Build an adaptive delivery system that continuously re-optimizes routes in response to dynamic real-world disruptions: new 
orders inserted mid-shift, road closures announced during active deliveries, high-priority order escalations that must be 
handled immediately, and vehicle breakdowns requiring order redistribution. Static route planning computed at shift start 
becomes suboptimal quickly in real operations — the system must react intelligently to each disruption within milliseconds. 
Students will implement a baseline static optimizer (Dijkstra + DP batch planning), then add an adaptive layer using greedy 
insertion for fast real-time order additions and DP re-optimization during low-disruption windows. The project emphasizes the 
engineering challenge of balancing re-optimization quality against computational budget — when a disruption occurs, the 
system has limited time to improve the solution before the next disruption arrives. 
Algorithm Usage 
Algorithm How It Is Applied 
Dijkstra's Algorithm Maintain a live road network graph with dynamic edge weights (updated by 
simulated traffic events and road closures). Run Dijkstra immediately after every 
network change to update all active couriers' routing costs. Implement an 
incremental Dijkstra update that only re-processes affected nodes (those 
reachable through a changed edge), reducing re-computation time for localized 
disruptions. 
DP Re-Optimization During quiet periods (no disruption in the last T seconds), run a full DP re
optimization of each courier's remaining delivery sequence. Use a time
constrained DP that cuts off after a configurable time budget (e.g., 200ms) and 
returns the best solution found so far. Track how much the DP-improved solution 
differs from the greedy-insertion solution in terms of total remaining route 
distance. 
Greedy Insertion 
Heuristic 
When a new order arrives, evaluate inserting it at every position in every active 
courier's route. Compute the insertion cost (additional distance) for each 
position. Select the minimum-cost insertion globally across all couriers and 
positions. This runs in O(n) per courier and produces a solution immediately, 
making it suitable for real-time order insertion within milliseconds. 
Bin Packing (Cargo 
Re-Assessment) 
When an order is added or cancelled, re-run bin packing to verify the courier's 
vehicle still has capacity. If adding a new order causes a capacity violation, the 
system must reassign some orders to another courier. Use greedy bin packing 
to determine which orders to offload to a new or less-loaded courier. Show the 
cargo manifest before and after each re-packing event. 
 
Expected Output 
Live delivery map: courier positions updated every simulation second, active routes drawn with remaining 
stops numbered, completed stops grayed out, and new orders appearing as blinking pins. 
Disruption event log: chronological list of all events — new order, road closure, vehicle breakdown, 
priority escalation — with timestamp, event type, algorithm used to respond, and solution quality change. 
Route quality tracker: a time-series chart showing total remaining route distance across all couriers over 
the simulation, dipping after DP re-optimizations and spiking after order insertions — illustrating the 
dynamic optimization cycle. 
Greedy vs. DP quality panel: after each DP re-optimization cycle, show distance saved vs. the greedy
insertion route, time taken for DP, and cumulative savings over the full shift. 
End-of-shift summary: total orders delivered, on-time rate, total distance driven, disruption count by type, 
average response time per disruption, and estimated fuel cost savings from adaptive re-routing.
